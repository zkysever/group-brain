# 怎么把评测集从 16 条补到 50 条（以及以后怎么继续补）

> 这份文档回答一个问题：`eval/queries.jsonl` 里那些行，到底怎么想出来的。
> 别从「算法应该测什么」出发，从「群里到底发生过什么」出发。

## 一、先说清楚为什么非得 50 条

16 条的时候，一条 miss 就是 6 个百分点。你上向量之后 Recall 涨了 0.05，
到底是真涨了还是碰巧某一条从 3 名挪到 4 名？样本太少，看不出来。

50 条是「一条查询 ≈ 2 个百分点」的量级，波动还在，但方向能看清了。
第 2 周要做的事是「关键词 → 关键词 + 向量」，判断标准写死在 EVAL.md 里：
**同一份 50 条，Recall@5 至少涨 15%，否则说明向量这条路对你这批数据没用。**

涨不动的时候你会想改评测集——所以规矩写在前面：**只增不删**。

## 二、三个硬规矩

1. **查询来自真实聊天记录**，不是你想出来的好问题。
   你编的问题系统答不上来，你也不知道是真不行还是问题本身不成立。
2. **query 用「人问人的说法」，expect 用「原文里最独特的一小段」。**
   不要两边用同一个词——那就是在测 `LIKE '%词%'` 能不能跑。
3. **写的时候不许去查这条会不会命中。**
   先写完 50 条再跑。一边写一边试，等于把评测集调成了「保证满分」，
   那这个数字以后一文不值。

## 三、具体怎么操作（一次 30 分钟）

工具已经给你了，在 `group-brain` 目录下：

```powershell
# 全部摊开看（226 条真人发言，一行一条）
.\.venv\Scripts\python.exe scripts\pick_queries.py --no-bot

# 只看含某个词的
.\.venv\Scripts\python.exe scripts\pick_queries.py --grep 鱼

# 随便抽 25 条，经常能翻到你自己都忘了的对话
.\.venv\Scripts\python.exe scripts\pick_queries.py --rand 25

# 看某一条的完整正文 + 前后各 3 条上下文
.\.venv\Scripts\python.exe scripts\pick_queries.py --id 233
```

翻记录，看到有意思的对话，就在脑子（或记事本）里过一遍：

> 「如果我三天后来搜这件事，我会敲什么字？」→ 那就是 `q`
> 「搜出来的那条消息里，有哪几个字是别的消息不会有的？」→ 那就是 `expect`

然后往 `eval/queries.jsonl` 里加一行，格式就一行 JSON：

```json
{"q": "你当时会敲的字", "expect": ["原文里独特的一小段"]}
```

`expect` 可以写多个，任意一个出现在前 5 条里就算命中。

## 四、50 条怎么凑（配比建议）

| 类型 | 大概几条 | 例子 | 在测什么 |
|---|---|---|---|
| 关键词型 | 15 | `扎口扎口`、`揉鱼肚` | 最基本的精确匹配，别在这一层就掉链子 |
| 对话提问型 | 15 | `问鱼能干什么`、`让鱼做个自我介绍` | 真实需求长什么样 |
| 二选一/接梗型 | 10 | `百事还是可口`、`英梨梨还是惠` | 群里最高频的句式 |
| 换词型（难） | 10 | `让鱼帮我把人开盒`（原话是「开个盒」） | 关键词的死穴，向量该救回来的就是这些 |

最后一类最重要，也最容易漏。**如果你补的 50 条里没有「问法和原话用词不重合」的，
那第 2 周做向量对比必然看不出差别**——不是向量没用，是你的评测集测不出来。

## 五、五个常见错误

1. **写成百科问答**：「什么是群聊记忆体」。群里没人这么说话。
2. **expect 太宽**：`expect: ["鱼"]`——483 条里 200 条都有「鱼」，等于没测。
3. **expect 太窄**：抄了原文里带空格/标点的一长串，前后挪一个字就匹配不上。
4. **只挑自己确定能命中的**。miss 也是数据，第 2 周要拿它证明向量有用。
5. **一条查询写了三个问题**。「问鱼喜欢谁顺便问它能不能改设定」——命中了也不知道算谁的。

## 六、这次已经帮你补到 48 条了（16 + 34，之后按你的意见删了 2 条）

2026-11-09，从 226 条真人发言里挑的 34 条，全部 `expect` 都确认在库里存在。你去掉两条「去贴吧学说话」之后是 48 条。
直接跑出来的结果：

```
查询条数      48
Recall@5    0.938  (45/48)
MRR         0.899
```

三条没中，而且三条是同一个病因：

| 查询 | 原话 | 为什么没中 |
|---|---|---|
| 生气的时候摆手 | 表情包 caption「别催我，一脸不耐烦地摆手」 | caption 里根本没有「摆手」这两个字 |
| 让鱼帮我把人开盒 | 机器人拒绝：「开盒这事儿我不干，这属于扒人隐私，违规」 | 前 5 条全是「帮我…」的请求本身，找不到那句拒绝 |
| 问鱼是不是忘了设定 | 「我设置了每日重置，鱼已经忘了…」 | 设置 ≠ 设定 |

**这三条留着，别删。** 第 2 周向量做出来之后，先看这三条有没有被救回来。
救回来了，说明向量真的在解决「换词」问题；没救回来，说明你 embedding 用错了，
或者 RRF 融合权重给错了。

## 七、你的下一步：审这 34 条

我挑的依据是「这条对话在群里出现过」，但**它们是不是真的有人会去搜，只有你知道**。
过一遍，做三件事：

- 觉得**不会有人这么搜**的 → 删掉那一行（这是唯一允许删的情况：不是删失败样本，是删不成立的查询）。
- 觉得**意思被我理解错了**的 → 改 `q` 的措辞，别改 `expect`。
- 想到**更值得测的** → 追加，超过 50 条也没关系，越多越稳。

改完重跑一次：

```powershell
.\.venv\Scripts\python.exe scripts\run_eval.py
```

把新的数字抄进 `EVAL.md` 的「对比实验」表第一行。这张表就是你以后简历上
「我说它有效」的唯一证据。

## 八、用什么工具打开改

**用 VS Code，别用记事本。** 你机器上已经装好了（`code` 命令直接能用）。

```powershell
# 在 PowerShell 里一条命令把整个项目打开
code C:\Users\Administrator\Desktop\group-brain
```

打开之后干这几件事：

1. 左边资源管理器 → `eval` → `queries.jsonl`，点开。
2. `Ctrl+P` 输入 `queries` 可以直接跳到这个文件，比点目录快。
3. 加完一行 `Ctrl+S` 保存。
4. 集成终端 `Ctrl+`` ` ``（反引号，Esc 下面那个键），在里面跑命令：

```powershell
.\.venv\Scripts\python.exe scripts\check_queries.py
.\.venv\Scripts\python.exe scripts\run_eval.py
```

**为什么不用记事本**：记事本不会告诉你哪一行 JSON 写坏了，也不会显示行号。
`queries.jsonl` 是一行一个 JSON，少个引号、末尾多个逗号、中文输入法带出全角引号，
在记事本里全都看不出来——只能靠跑一遍报错去猜。

### 三个必须知道的坑

1. **右下角编码必须是 `UTF-8`**。如果显示 `UTF-8 with BOM`，
   点它 → `Save with Encoding` → 选 `UTF-8`，再保存一次。
   带 BOM 的话 Python 读第一行会多出一个看不见的字符，整份文件第一条就解析失败。
2. **中文输入法**：逗号和引号在中文状态下是 `，` `“”`，JSON 只认 `,` `"`。
   写 JSON 时把输入法切到英文。
3. **行尾不要多写逗号**。JSON 数组最后一项后面不能有逗号（跟 JS 不一样）。

### 改坏了怎么救

这个项目是 git 仓库，改砸了能直接退回上一个提交：

```powershell
git diff eval/queries.jsonl          # 看我改了哪些行
git checkout -- eval/queries.jsonl   # 全退回去
```

**先跑 `check_queries.py`，再跑 `run_eval.py`。** 前者只说格式对不对（快），
后者才告诉你检索效果（慢，而且格式错会直接崩）。
